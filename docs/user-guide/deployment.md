# Deployment

The chart in `charts/rag-app` deploys the whole stack — the Java app, PostgreSQL
with pgvector (StatefulSet + PVC), and Redis — from a single release.

## Install

```bash
helm install rag ./charts/rag-app -n rag --create-namespace
```

Check the release:

```bash
kubectl -n rag get pods
kubectl -n rag get svc,ingress,hpa
```

## Provide the LLM API key

`/api/chat` needs a real key. A placeholder secret is generated by default so the
app boots; supply your own key via an existing Secret:

```bash
kubectl -n rag create secret generic my-llm-key --from-literal=api-key=<YOUR_KEY>
helm upgrade rag ./charts/rag-app -n rag \
  --set app.secrets.llmApiKey.existingSecret=my-llm-key
```

The key referenced inside the Secret defaults to `api-key`
(`app.secrets.llmApiKey.key`).

## Images

Every component image is a separate, fully overridable block
(`registry` / `repository` / `name` / `tag` / `pullPolicy`). `global.registry.url`
rewrites the registry for all three at once — useful behind a private mirror.

```bash
helm install rag ./charts/rag-app -n rag \
  --set global.registry.url=my.registry/mirror \
  --set app.image.repository=myteam --set app.image.tag=0.1.0 \
  --set postgres.image.tag=pg17
```

If the app image is only loaded locally (e.g. into kind), set
`--set app.image.pullPolicy=IfNotPresent`.

## Values reference

### Global

| Value | Default | Purpose |
| --- | --- | --- |
| `global.registry.url` | `""` | Override registry for all images |
| `global.pullSecret` | `""` | imagePullSecret applied to all pods |
| `global.imagePullPolicy` | `IfNotPresent` | Default pull policy |
| `global.storageClass` | `""` | Override storage class everywhere |
| `replicaCount` | `1` | App replicas (ignored when autoscaling is on) |

### App (`app.*`)

| Value | Default | Purpose |
| --- | --- | --- |
| `app.image.{registry,repository,name,tag,pullPolicy}` | `docker.io/your-org/rag-app` | App image (tag defaults to chart appVersion) |
| `app.service.{type,port}` | `ClusterIP`, `8080` | Service |
| `app.config.llm.baseUrl` / `.model` | Groq defaults | LLM endpoint + model |
| `app.config.embedding.dimensions` | `384` | Vector dimension |
| `app.config.cache.similarityThreshold` | `0.95` | Cache hit threshold |
| `app.config.rateLimit.requestsPerMinute` | `60` | Rate limit |
| `app.secrets.llmApiKey.existingSecret` / `.key` | `""` / `api-key` | Where to read the LLM key |
| `app.resources` | 250m/1Gi → 2/2Gi | Requests/limits |
| `app.probes.{liveness,readiness}` | see values.yaml | Probe tuning |

### PostgreSQL (`postgres.*`)

| Value | Default | Purpose |
| --- | --- | --- |
| `postgres.enabled` | `true` | Deploy Postgres (disable to use an external DB) |
| `postgres.image.*` | `docker.io/pgvector/pgvector:pg16` | Image |
| `postgres.auth.{database,username,password}` | `ragdb` / `rag` / `rag` | Credentials |
| `postgres.auth.existingSecret` / `.passwordKey` | `""` / `postgres-password` | Use an existing Secret |
| `postgres.persistence.{enabled,size,storageClass,accessModes}` | `true`, `10Gi` | PVC |
| `postgres.resources` | 250m/256Mi → 1/1Gi | Requests/limits |

### Redis (`redis.*`)

| Value | Default | Purpose |
| --- | --- | --- |
| `redis.enabled` | `true` | Deploy Redis (disable to turn off caching infra) |
| `redis.image.*` | `docker.io/library/redis:7-alpine` | Image |
| `redis.auth.{enabled,password,existingSecret,passwordKey}` | `false` | Optional `requirepass` auth |
| `redis.persistence.{enabled,size,storageClass}` | `false`, `1Gi` | PVC (StatefulSet when enabled, else Deployment) |

### Ingress, scaling, security

| Value | Default | Purpose |
| --- | --- | --- |
| `ingress.enabled` | `true` | Create an Ingress |
| `ingress.className` | `nginx` | IngressClass |
| `ingress.host` | `rag.local` | Hostname |
| `ingress.tls.{enabled,secretName}` | `false` | TLS termination |
| `ingress.auth.basic.{enabled,secretName}` | `false` | nginx basic-auth (htpasswd Secret) |
| `autoscaling.{enabled,minReplicas,maxReplicas,targetCPUUtilizationPercentage}` | `false`, 1–5, 70% | HPA |
| `serviceAccount.{create,name}` | `true` | ServiceAccount |
| `networkPolicy.enabled` | `false` | Restrict pod traffic (DNS + DB + Redis + 443) |
| `metrics.enabled` | `true` | Prometheus pod annotations |
| `metrics.serviceMonitor.enabled` | `false` | Prometheus Operator ServiceMonitor |
| `podSecurityContext`, `securityContext` | non-root, read-only rootfs, drop ALL | Hardening |

## Production checklist

- Supply a real LLM key via `app.secrets.llmApiKey.existingSecret`.
- Supply DB/Redis passwords via `*.auth.existingSecret` (don't ship defaults).
- Set an appropriate `postgres.persistence.storageClass` and `size`.
- Enable `ingress.tls` and either `ingress.auth.basic` or `networkPolicy` — the
  Ingress is unauthenticated by default.
- Consider `autoscaling.enabled=true`; note the rate limiter is per-pod (see
  [Operations](operations.md#rate-limiting)).
- Scrape metrics via `metrics.serviceMonitor.enabled=true` (Prometheus Operator) or
  the pod annotations.

## Rendering / validating manifests

```bash
helm lint charts/rag-app
helm template rag charts/rag-app | less        # inspect rendered YAML
helm template rag charts/rag-app --set redis.enabled=false   # try overrides
```

## kind (local cluster)

`scripts/e2e-kind.sh` creates a kind cluster, loads the images, installs the chart,
and runs ingest/health/metrics checks. Note it requires a working kind control
plane; on hosts where kind cannot start, use `scripts/e2e-compose.sh` instead to
validate the image against real pgvector + Redis containers.
